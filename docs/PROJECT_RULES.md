\# Earl Project Rules



1\. Keep new features modular.

2\. Do not put permanent features into tutorial/test files.

3\. Temporary experiments belong in `dev/`.

4\. Each major capability should have its own module or folder.

5\. Use Git commits often with clear messages.

6\. Do not commit secrets, passwords, API keys, or `.env`.

7\. Do not let the LLM directly execute arbitrary code.

8\. The LLM decides high-level goals; deterministic code performs actions.

9\. If a task is unclear, ask for the exact numbered section to be broken down further.

10\. Test each feature in Minecraft before treating it as complete.
